## 1. Script generation: status (answered from evidence)

- **Not yet switched.** Production is still 100% local qwen3.5:9b. Phase 18 is in progress:
  18.1 (provider) and 18.2 (router) are done, and 18.3 (Settings) is in implementation. The
  `AI_MODE` default stays `local` until Gate B-9 passes (plan Amendment C).
- **Local, after Phase 17** (`docs/operations/phase17-gate-b8r.md`): B1 8-min 5/5, owner config
  4/4, about 100–190 s per script job. It reaches this through many repair rounds, because
  first-pass generation lands at a median 0.60× the section target.
- **Cloud, indicative only** (`docs/operations/enh011-nemotron-smoke.md`): Nemotron 3 Super hit
  199 of 200 words on the first pass, in 8–28 s per section, from a single sample. Full-pipeline
  time and completion are **not yet measured**. The first full-pipeline attempt died on the
  shared router deadline, which 18.2 fixed.
- **Expectation:** accuracy likely improves (fewer repairs). Speed is uncertain, because free-tier
  queueing and overloads can offset the fewer repairs. **Gate B-9 is the measured answer**
  (completion, repairs per job, wall time, fallback rate, cloud vs local).

## 2. Thumbnail: current mechanism

- Five static background PNGs (`frontend/static/thumbnail_templates/*.png`).
- The AI suggests only the text (headline) and palette; Pillow renders them onto a template.
- No generated imagery, so every episode reuses the same five backgrounds.

## Decisions (owner, 2026-09-24)

| ID | Decision | Rationale |
|---|---|---|
| **D25** | **Thumbnail: A first, then trial B locally.** (A) Once Phase 18 enables the cloud, the cloud model writes the thumbnail text, with no extra work. (B) Afterwards, a short spike phase: a local image model on the RTX 3060 generates a per-episode background; Pillow still renders the text (generated text in images is unreliable); the 5 templates stay as the fallback. | Free and private. Phase 18's cloud-first mode frees the GPU: qwen (~7 GB) then only loads as a fallback, so an image model (~8–10 GB) can use the 12 GB card. |

Options considered and not chosen: (C) stock photos (Pexels/Unsplash), which needs a network,
a key and a licence review; (D) cloud image generation, which had no free image models in the
owner's OpenRouter list.

## Phases

### Phase 19 (proposed, after Phase 18): Local AI thumbnail backgrounds, spike (ENH-012)

1. Pick the model by spike, checking VRAM fit, per-image time, licence and quality:
   - FLUX.1-schnell (4-step, Apache-2.0);
   - SDXL-Turbo / SDXL.
   Measure with Ollama unloaded vs loaded.
2. Add a background-generation step behind a feature flag. The prompt comes from the episode
   topic, and the cloud model writes it. Output is 1280×720 plus a 9:16 variant. Pillow overlays
   the text with the existing templates' text-zone logic.
3. Fallback: on any failure (no GPU, out of memory, model missing), use the existing 5 templates.
   This mirrors the Phase 18 fallback.
4. Packaging: the model weights are **not** bundled in the .exe; they download on first use or
   come from a documented path, as the Ollama model does today.
5. A quality gate: the owner compares generated vs template thumbnails on 5 real episodes.

## Risks / open questions

- The dependency weight: torch + diffusers is several GB of install and a big hit to the .exe.
  Consider running the image model as a separate local service (e.g. ComfyUI / an sd-server
  style process) instead of in-process.
- VRAM contention with the qwen fallback. The image step must run only when Ollama has unloaded
  (`keep_alive`), or unload it explicitly.
- Model licence terms must be checked before choosing.
