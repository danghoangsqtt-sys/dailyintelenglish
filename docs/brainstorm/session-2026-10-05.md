# Brainstorm session 2026-10-05 — AI background music (Phase 22)

- **workflow_version:** viepilot 2.19.0 (vp-brainstorm 1.1.0)
- **Mode:** continue the earlier plan (D37 priority 3 "music from text"; the owner's reference was
  ACE-Step-1.5; Phase 22 queued after Phase 24 by D41).
- **Owner request (verbatim):** "tạo cơ chế làm nhạc nền cho video để không bị dính bản quyền,
  nhạc được tạo bằng AI, nhạc không lời có giai điệu phù hợp với chủ đề video"
  *(a background-music mechanism for the videos that avoids copyright problems: AI-generated,
  instrumental, with a melody that suits the video's topic)*.

## Current state (from the code)

- **Music Library** (`/music`, Task 1.10): the owner uploads MP3/WAV files (50 MB limit,
  magic-byte check). There is no metadata table; the library is just the files in
  `data/music_library/`.
- **Mixing** (`audio_service._mix_project_sync`):
  - the chosen track is looped to the episode length;
  - a static duck caps it at a flat `MUSIC_DUCKING_MAX_DBFS`;
  - the final mix is normalized to −16 LUFS.

  It is not speech-aware.
- **GPU:** RTX 3060 12 GB. A shared VRAM manager (Task 20.1) lets image workers lease the card
  and evict Ollama.

## Research (2026-10-05)

| Candidate | Licence / data | Fit |
|---|---|---|
| **ACE-Step 1.5** (ACE Studio + StepFun, `ACE-Step/Ace-Step1.5`) | **MIT**; the model card says the output may **strictly be used for commercial purposes**; trained on licensed, royalty-free/public-domain and MIDI-synthesized data | <4 GB VRAM; "<10 s per song on an RTX 3090"; loops up to 10-minute pieces; instrumental; repaint/extend (base model); turbo 8-step DiT + 0.6B/1.7B/4B LM planner |
| MusicGen / MAGNeT (Meta) | weights CC-BY-NC 4.0 | **no**: non-commercial, and the channel will be monetized |
| Stable Audio Open | Stability Community Licence (registration) | **no**: the owner declined registration-bound licences in Phase 20 (Q1) |
| YuE, DiffRhythm | Apache-2.0 | song-with-vocals focus; not needed for an instrumental bed |

## Decisions

| ID | Decision | Rationale |
|---|---|---|
| **D43** | Model: **ACE-Step 1.5**, local, in its own isolated venv and subprocess worker under the Task 20.1 GPU lease | Only candidate that is commercial-safe, trained on licensed data, and small enough (<4 GB) to share the 12 GB card |
| **D44** | Structure: **one instrumental background bed per episode, plus intro/outro emphasis** (louder in the Remotion intro/outro); no per-scene music | Cohesive, cheap; per-scene changes risk feeling choppy |
| **D45** | Control: **the AI proposes and the owner picks**. The cloud text model writes a music brief from topic/genre/CEFR (style family, instruments, BPM, mood); the owner can edit it; **3 short previews** are generated, the owner picks one, then the full-length track is generated | Same review pattern as the storyboard (E3); keeps the owner's taste in the loop |
| **D46** | Storage: generated tracks go **into the Music Library**, reusable, each with a **provenance record** (model + licence, brief/prompt, seed, duration, created at, app version). The YouTube description gains a music credit line automatically | Proof if a copyright claim ever appears; reuse across episodes |
| **D47** | Length: **a spike decides** between (a) one full-length generation matching the episode and (b) a 2–3 min loopable piece repeated with crossfades; the owner listens and picks | Long-form stability vs audible looping is an empirical question |
| **D48** | Mixing: **speech-aware ducking**: lower under speech, a gentle lift in pauses, fuller in intro/outro, using the per-line timestamps that already exist | Music matters more once it's tailored; a flat duck wastes it |
| **D49** | Style families offered to the AI: **Lofi/chill**, **Acoustic/piano warm**, **Upbeat/corporate bright** (Vietnamese traditional fusion not selected for now) | Owner choice; maps naturally to genres (small talk/life → lofi; storytelling/interview → acoustic; news/instructions/work → upbeat) |

### Phase 22 — AI background music (ACE-Step 1.5)

1. **22.1 Spike** (GPU, owner listens):
   - install ACE-Step 1.5 in `venv-music` (Python/torch compatibility to be found);
   - measure VRAM, speed and quality for the three style families;
   - compare the two length strategies (D47);
   - **upload one track unlisted to YouTube to check Content ID** (owner action).
2. **22.2 Music worker + library v2:**
   - a subprocess worker (load / generate / unload) under the GPU lease;
   - an additive `music_tracks` table (provenance) beside the existing files;
   - the Library UI shows source and provenance, and can generate a track standalone from a brief.
3. **22.3 AI music brief + previews:**
   - the gateway writes a brief from the project (validated, with a fallback to the style family
     mapped from the genre);
   - the owner edits it in Step 4;
   - 3 short previews → pick → full-length track, attached to the project.
4. **22.4 Speech-aware ducking:**
   - a timestamp-driven gain envelope in `audio_service`;
   - intro/outro levels in the Remotion and ffmpeg paths;
   - the −16 LUFS target is kept.
5. **22.5 Credit + provenance:** a YouTube description music credit line, and a provenance export
   per track.
6. **22.6 Gate B-17:** an owner listening test on 3 real episodes (one per style family).

## Open questions

- ACE-Step 1.5 install footprint and Python/torch compatibility on the owner's machine (the image
  venv uses Python 3.14; music may need 3.11/3.12 like `venv-kokoro`).
- Which LM size: 0.6B or 1.7B. The 4B would need more VRAM, so the spike measures it.
- Loop seam quality, and whether the "complete/extend" mode can make loop-perfect endings.
- Content ID behaviour on AI music (an empirical check in 22.1).
- A default music level per style family (lofi is softer than upbeat).
