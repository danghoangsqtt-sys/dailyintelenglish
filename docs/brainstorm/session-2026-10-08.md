# Brainstorm session 2026-10-08 — Reusable activity cutaways for talking characters

- **Status:** In Progress
- **workflow_version:** viepilot 2.19.0 (`vp-brainstorm` 1.1.0)
- **Language:** Vietnamese conversation; English repository artefacts
- **Context:** continuation of the owner's previous Claude Code discussion after the Phase 32 talking-sprites preview
- **Trigger:** the owner liked the talking-character result but asked whether the video should also show illustrative pictures such as Alex exercising or Lina cooking. The owner accepted the proposed direction before the prior Claude session ran out of tokens.

## Recovered owner intent

1. Add reusable activity illustrations for Alex and Lina.
2. During an illustration beat, cut away from the talking sprites to a full-frame still, then return to the sprite scene.
3. Do not composite the activity picture into the live sprite layout; this avoids face, costume and scale mismatches.
4. Keep captions over the cutaway.
5. Build a reusable library from owner-created 16:9 pictures and match them to later storyboards by activity.

## Current code evidence

- `docs/implementation/phase-32-talking-sprites.md` already specifies that insert stills cut to their full-frame illustration and that the Shot Library remains useful for illustration inserts.
- The implemented `podcast_sprites` path does not yet do this. `_build_sprite_props()` maps an insert beat to the previous scene plate and `Sprites.tsx` always draws the scene background plus both sprites.
- The approved Demo Episode storyboard already contains three insert beats, so the feature can be verified without inventing a synthetic workflow.
- The existing Shot Library cannot currently hold reusable inserts: the database restricts `kind` to `single`, `duo_close`, or `duo_wide`, and its tests explicitly reject `insert` shots.
- Phase 32 tasks 32.1–32.5 are complete; Gate B-22 is still planned.

## Decisions carried forward from the prior discussion

| ID | Decision | Rationale |
|---|---|---|
| D63 | Add illustrative activity cutaways to `podcast_sprites`. | The talking sprites remain the main presentation, while activity pictures add visual variety and explain actions that sprites cannot perform. |
| D64 | An activity illustration is a **full-frame cutaway**, not an image composited with Alex/Lina's live sprites. | It avoids visible face, costume, scale and lighting mismatches between independently generated assets. |
| D65 | Captions remain visible during the cutaway; the talking sprites are hidden until the cutaway ends. | Dialogue remains readable and the illustration gets a clean frame. |
| D66 | Create a dedicated, database-backed **Activity Library**, shown as a separate card/section on the existing Shot Library page. Each asset records its character, canonical activity, keyword aliases, review state and usage count; it is not tied to a scene. | Activity cutaways are scene-independent and use different matching rules from framed dialogue shots. A dedicated model avoids making `shot_library` fields nullable or adding insert-specific exceptions while keeping all visual assets in one UI. |
| D67 | A cutaway starts at the beginning of its insert beat and lasts until the beat ends or **6 seconds**, whichever comes first. The storyboard prompt aims for insert beats of roughly 3–6 seconds. A short beat is never extended into the next line; if a beat is longer than 6 seconds, its remaining audio continues over the restored sprite scene. Use an approximately 0.3-second crossfade in and out. | Timing remains anchored to real line timestamps and never changes the audio or leaks an illustration into unrelated dialogue, while the cap prevents a still from becoming visually stale. |
| D68 | Match with a **controlled alias dictionary and deterministic scoring**. Score the canonical activity and alias phrases against the insert beat's `action` plus its dialogue text. Prefer a character-specific asset when it names the speaking character, but also allow a subject-neutral generic asset for any speaker. Use a picture only above the documented threshold; ties rotate toward the least-used/least-recently-used approved variant. Do not call an AI model during render. | This handles ordinary wording variants while remaining fast, explainable, reproducible and testable. Generic assets reduce the number of Alex/Lina-specific pictures required; usage history adds variety without allowing a weak semantic match to win. |
| D69 | If no approved asset clears the matching threshold, or the selected file is missing/invalid, continue rendering the existing scene and talking sprites. Step 5 reports the unmatched character/activity before render. Do not block the video, choose a below-threshold picture, or generate a new picture automatically. | A missing illustration reduces variety but never breaks a talking-character video or silently shows an unrelated image. |
| D70 | Activity assets may be **character-specific** or **generic** (`character_id = null`). Generic assets can show an environment, objects, hands, or anonymous/background people: for example people walking for exercise, or a busy/in-progress kitchen for cooking. Optional context tags such as morning, afternoon, evening, indoor and outdoor refine the choice when the dialogue provides that context. | The illustration only needs to communicate the activity; it does not always need to reproduce Alex or Lina. This broadens reuse across characters and episodes while avoiding identity drift. |
| D71 | Bulk-import activity pictures through `data/library/activities_inbox`. The filename supplies initial metadata using `<scope>__<activity>__[context]__[variant]`, where scope is `generic` or a character name; examples: `generic__exercise__morning__01.png`, `generic__cooking__kitchen__01.png`, `alex__reading__indoor__01.png`. Imported assets start as `pending`; the existing Shot Library page shows their preview and lets the owner correct scope, activity, context and aliases before approval. Only `approved` assets may match. | Filename import makes a prompt pack quick to load, while the review step prevents a naming mistake or unsuitable image from silently entering a video. |
| D72 | Seed the library with **20 generic activities**, one approved picture each: exercise/workout; walking; jogging/running; cycling; cooking; baking; eating a meal; drinking coffee/tea; grocery shopping; cleaning/tidying; gardening; reading; studying/writing notes; working on a laptop; meeting/presentation; commuting by bus/train; driving; travelling/packing; relaxing/listening to music; sleeping/morning routine. Add variants or character-specific pictures later from observed coverage needs. | A generic-first pack provides broad coverage with about half the asset work of separate Alex and Lina packs. Usage and unmatched-beat reports can guide later expansion instead of guessing combinations up front. |
