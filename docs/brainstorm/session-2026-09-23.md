## Context (evidence, not re-derived)

- Large cloud models hit the section word target almost exactly on the first pass: Nemotron 3
  Super and Ultra returned 199 words against a target of 200. Local qwen3.5:9b's first pass lands
  at a median 0.60× (15/118 within ±15%). This is the weakness Phases 14–17 keep repairing.
- The OpenRouter free tier is unreliable as a sole provider. Seen during testing: `503
  overloaded` (Ultra: 7/8 calls), 429s, latency from 8 s to 5 min, a 403 on a restricted model,
  and upstream errors returned as **HTTP 200 with an `error` body**. `json_schema` mode returned
  malformed JSON; a plain prompt asking for JSON worked.
- **The router already has the needed mechanism:** `hybrid` mode (primary, then a visible
  fallback) plus a circuit breaker. But:
  - (a) the order is hard-wired local → Gemini;
  - (b) one `deadline_seconds` covers the whole route, so a slow primary leaves no time for the
    fallback. The smoke-test jobs died exactly this way ("AI router deadline of 120.0s exceeded").

## Decisions (owner, 2026-09-23)

| ID | Decision | Rationale |
|---|---|---|
| **D21** | **Cloud first, local qwen as automatic fallback** for all AI writing (script, learning, thumbnail and YouTube text). This supersedes D9/D11 (local-only) as the default. The `DIE_AI_ALLOW_CLOUD` kill switch stays: set to false, it returns to local-only. | Cloud quality and instruction-following are much better. The fallback means a cloud outage degrades the job instead of failing it. |
| **D22** | **Start on the free tier** (default model `nvidia/nemotron-3-super-120b-a12b:free`). Measure how often the fallback fires; consider paid only if that rate is too high. The model id is one configuration value. | Costs nothing to start. The paid option is cheap (roughly $0.01 per script with Super, an estimate) if it's ever needed. |
| **D23** | **Replace the dedicated Gemini provider with one generic OpenAI-compatible provider.** Gemini stays reachable through it (OpenRouter, or Google's OpenAI-compatible endpoint) if ever wanted. | One cloud mechanism instead of two; less code. |
| **D24** | **Configure the API key, base URL and model in the Settings page**, stored in the local DB like today's Gemini key: write-only and masked. `.env` (`DIE_OPENAI_COMPAT_*`) supplies the defaults. | Works for the packaged `.exe` without editing files; follows the existing pattern. |

## Proposed architecture

```
AIRouter (roles: primary / fallback, instead of fixed local / gemini names)
 ├─ primary:  OpenAICompatProvider  (OpenRouter / Zen / NVIDIA / Google-compatible)
 │    - chat/completions, plain prompt-only JSON (no response_format), fence strip
 │    - reasoning: {"exclude": true}
 │    - 200-with-error body, 429 and 5xx → transient; 401/402/403/404 → config error,
 │      no retry, go to fallback immediately
 │    - its own time budget (≈ 150 s, constant)
 ├─ fallback: OllamaProvider (qwen3.5:9b) with its OWN time budget (not what's left
 │            of the primary's)
 └─ circuit breaker on the primary: after N consecutive failures, go straight to fallback
    for the cooldown period
Per-call metrics already record provider/model; add fallback_used per call and a
fallback-rate readout (D22's measurement).
```

Unchanged:
- The pipeline's validation, repair logic and thresholds.
- TTS, audio and video (not LLM-driven).
- Phase 17's global-stage fixes still matter, because qwen is the fallback.

## Phases

### Phase 18 — Cloud-First AI with Local Fallback (ENH-011), proposed; starts after Phase 17 closes

1. **18.1** `OpenAICompatProvider` plus its tests, with a fake HTTP transport. Covers every
   error shape seen in the smoke test (200-with-error, 429, 503, 402/403, malformed JSON, code
   fences).
2. **18.2** Router generalisation: primary/fallback roles, a `cloud_first` mode, separate
   per-provider time budgets, the circuit breaker on the primary, and `fallback_used` per call.
   Remove the Gemini provider (D23) and migrate the stored `gemini_api_key` setting (deprecate,
   don't silently reuse).
3. **18.3** Settings page + API: base URL, model and key (write-only, masked; a "test
   connection" button), `.env` defaults, and `/api/ai/health` showing cloud reachability and
   the active model. The UI warns that topics must not contain personal data (free-tier data
   policy).
4. **18.4** Fallback-rate readout: jobs aggregate the share of calls served by the fallback, as
   D22's decision input. Shown in the health payload or on the dashboard.
5. **18.5** Gate B-9 (PM): the same protocol as B-7/B-8, run as an A/B pair: `cloud_first`
   (free Super) vs local. Measures completion, content checks, repairs, wall time and fallback
   rate. Media timing is re-checked because word counts will change.

## Risks / open questions

- The free-tier daily request cap for this key isn't reported by the API. Measure it in Gate B-9.
  A script job uses about 10–15 calls.
- The free offering can change or end at any time. The fallback covers this functionally, but
  quality then drops back to qwen.
- The pace and word-budget calibration was built on qwen. Cloud outputs land closer to target,
  so the repair counts should drop. Verify in Gate B-9 rather than assume.
- Privacy: free-tier providers may use prompts to improve their models. Podcast scripts are not
  confidential, but personal data must stay out of topics (UI note in 18.3).
- The cloud per-call budget (≈ 150 s) and the circuit-breaker threshold are to be set in the 18.2
  design from the smoke-test latencies (8–296 s).
