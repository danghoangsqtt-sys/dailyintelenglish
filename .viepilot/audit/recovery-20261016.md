## Tier 3 — Code correctness: 2 lỗi đã tái hiện

### BUG-042 — High: cancellation làm rò transaction dùng chung

`backend/db/transactions.py:43` chỉ rollback trong `except Exception` tại dòng61. `asyncio.CancelledError` không đi qua nhánh này. Trên DB in-memory, cancel coroutine sau INSERT giải phóng lock nhưng vẫn để `db.in_transaction=True`; read kế tiếp thấy dữ liệu chưa commit và write transaction kế tiếp commit luôn dòng của request đã hủy.

Đây là lỗi helper hiện có, không phải bằng chứng production đã mất/hỏng dữ liệu hay nguyên nhân phiên chat mất mạng. Phần explainer đang làm có `_write_transaction` bắt riêng cancellation để bảo vệ các writes của nó; các caller helper chung vẫn cần xử lý thống nhất. Yêu cầu fix bounded + regressions trước khi mở rộng phạm vi. Python khuyến nghị cleanup khi cancellation và propagate sau cleanup; `CancelledError` kế thừa trực tiếp BaseException. [Python 3.14 task cancellation](https://docs.python.org/3.14/library/asyncio-task.html#task-cancellation).

### BUG-043 — Medium severity: PATCH explainer invalid trả 500

`ExplainerPlanPatch` (`backend/schemas/explainer.py:220`) kiểm tra unlock map nhưng chưa kiểm tra uniqueness của aspects/segment IDs. Uniqueness chỉ kiểm tra khi tạo `ExplainerPlan` trong `publish_draft` (`backend/library/explainer_service.py:162`). Kết quả từ API thật trong TestClient: PATCH với `["16:9","16:9"]`, hoặc hai segment cùng ID nhưng anchors/coverage vẫn hợp lệ, trả **500 / Internal Server Error dạng plain text** thay vì 422 với error envelope. Raw Pydantic ValidationError tạo trong service không phải FastAPI RequestValidationError. Bản kế hoạch trước vẫn giữ revision, không thấy lỗi rollback trong reproductions này.

Đưa invariant vào request schema và/hoặc chuyển service schema failures thành typed app error; không che mọi exception thành 422. [FastAPI error handling](https://fastapi.tiangolo.com/tutorial/handling-errors/), [Pydantic model validators](https://pydantic.dev/docs/validation/latest/concepts/validators/).
