# BUG: Cancelled shared write transaction leaks into the next request's commit

## Summary

`write_transaction` catches Exception but not asyncio.CancelledError. Cancellation after a SQL write releases the app-wide lock without rollback; the shared connection remains in a transaction, a subsequent reader sees the abandoned write, and the next successful writer commits it.

## Details

- **Severity**: high; correctness of shared-connection isolation.
- **Affected files**: `backend/db/transactions.py:43`, cancellation paths of its callers.
- Reproduced with actual helper and aiosqlite `:memory:`: cancel after INSERT; `db.in_transaction=True`, lock unlocked; subsequent read sees cancelled row; next write commits both rows.
- Explainer's local `_write_transaction` wrapper already adds cancellation rollback. This does not fix other callers of the shared helper.
- No evidence of production data corruption is claimed. The interrupted chat/network session is not attributed to this bug.

## Acceptance Criteria
