## PM Correction (2026-09-11)
On reflection this is the correct behavior, not a gap — reversing the request above. This bug's actual Acceptance Criteria (the only binding contract) never mention `temperature`; they are entirely about **structural** determinism (a valid, schema-conforming JSON shape every call), which BUG-011 delivers via `responseJsonSchema`. Pinning `temperature` low would actively regress the product: `step2_script.js`'s per-line "Regenerate" and "Regenerate All", and `step3_learning.js`'s "Regenerate Pack", all resend the *same* prompt expecting *different* wording each time — near-zero temperature would make Gemini return near-identical output on every regenerate click, defeating the feature. Leaving sampling temperature at Gemini's default (unset) is the deliberate, correct choice; structural determinism is guaranteed by schema + semantic validation instead. **Accepted, no code change required.**
