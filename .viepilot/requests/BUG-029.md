## Summary
The Activity Library holds 25 approved pictures each for Alex and Lina (`exercise`, `working out`, `morning routine`,
`cooking`, ...), yet the Demo Episode used only generic pictures. `video_renderer_remotion.py:357-360` (and the coverage
endpoint `app/api/visuals.py:508`) pass a character to `activity_matcher.match_activity` only when `beat.speakers` holds
exactly one index. The storyboard prompt (`prompts/storyboard/storyboard.txt:31`) tells the AI to set `speakers: []` for
objects, places and crowds, and the AI did so for all three Demo inserts (`project_beats` rows 1, 3, 7), including Alex's
"stretch for ten minutes" line. With no character, the matcher can only return generic pictures.

## Owner decision (D76, 2026-10-12)
Prefer the picture of the character **who speaks the beat's line(s)** when one exists for the activity; otherwise use the
generic picture. (`beat.speakers`, when set to one character, still names that character.)

## Acceptance Criteria
- [ ] When `beat.speakers` is empty, derive the speaker from the beat's lines (line speaker → cast index → character);
      a beat spanning two speakers uses a documented rule (plan to decide: the line that names the action, else the first line).
- [ ] Render path and Step 5 coverage use the same rule (one shared helper).
- [ ] Unit tests: Alex line about stretching → Alex `exercise`/`working out`; no character picture → generic; other
      character's picture never chosen.
- [ ] Demo Episode re-render shows character pictures where they exist.
