## Summary
7 of 9 frontend pages carry their own `<style>` block: 992 total lines of per-page
inline CSS versus 227 lines in the shared `frontend/static/css/style.css` — roughly
4.4x more CSS living scattered across pages than centralized. This alone would just be
a maintainability concern, but independent verification found **concrete, real visual
drift**, not merely duplication:

- Shared `style.css` defines disabled-button opacity as `.btn[disabled] { opacity: .58; ... }`.
- `music_library.html` locally redefines it as `.btn:disabled { opacity: 0.55; ... }`
  (different selector mechanism, different opacity value).
- `step7_youtube.html` locally redefines it again as
  `.btn[aria-disabled="true"] { opacity: 0.55; ... }` (a third selector mechanism, same
  0.55 value, still inconsistent with the shared 0.58).
- `step6_thumbnail.html` overrides `.btn-sm { padding: 7px 11px; font-size: 12px; }`
  locally, vs. the shared `.btn-sm { min-height: 30px; padding: 5px 10px; font-size: 12px; }`
  — a real padding mismatch.

Net effect: a disabled button (or a small button) looks subtly different depending on
which page it's on, purely as a side effect of independent per-page CSS rather than an
intentional design decision.

## Risk assessment
Low functional risk (cosmetic only), but a real, user-visible inconsistency, and a
maintenance hazard: future edits to the shared `.btn` styling will silently not apply
on the 4 pages that locally override disabled/small-button styling.
