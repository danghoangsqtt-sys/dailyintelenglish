## Summary

**Propose plan** on a real Solo project ended `error` / `explainer_invalid_proposal`: "Provider response failed schema validation (60 error(s))" after the first call and one repair (Gemini 3.1 Flash-Lite). `backend/ai/prompts/storyboard/explainer.txt` says "Return ONLY JSON matching the supplied schema", but cloud providers are prompt-only JSON (`openai_compat_provider.py` never sends `json_schema`; only Ollama receives it as `format`). The prompt has no Output Format section, so Gemini invents field names (`segment_id`, `narrative_anchors`, `visuals`). Tests use a fake router, so this was never exercised with a real cloud model.

Read-only replay on the same snapshot:
- current prompt: 3/3 invalid schema;
- prompt + JSON Schema + shape example: schema valid, but 3/3 refused for coverage — the model miscounted a 51-token line and ended at 50;
- additionally giving each line its `token_count` and the end rule: **5/5 valid on the first call**.

## Acceptance criteria
- The explainer prompt includes an Output Format section with the exact JSON Schema of `ProposedExplainerSegment` wire data and a placeholder shape example.
- Each script line in the prompt carries `token_count`; the prompt states that a segment ending a line uses `end.token_index == token_count`.
- Regression test: the rendered prompt contains the schema field names and token counts.
- Real check: a proposal on the Lina test project completes with the cloud provider.
