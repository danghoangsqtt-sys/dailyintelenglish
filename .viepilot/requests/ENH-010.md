## Summary
After 16.4 removed repetition as a failure class (0.00% in 9/9 completed scripts), Gate B-7's two
script failures were both **global word-count overshoots**:
- B1 8-min run 1: 1,124 / 1,000, plus a 1.07% repeated-8-gram ratio, so a mixed failure;
- the B1 5-min sample: 703 / 625, word count only.

The pipeline repairs section length, but nothing repairs a total that ends up more than 10% over
target. A mixed failure is also excluded from Task 14.13's repetition repair by design, so it
dies without any repair attempt.

## Watch item (same gate)
The runner's `has_outro` heuristic missed two scripts at B-7 (0 at B-6):
- B1 run 4 is a false negative. Its real sign-off sits two lines before the last line.
- Owner run 1 genuinely ends on a call to action with no goodbye.

It is possible, not proven, that 16.4's rule 5 ("never repeat the same summary/takeaway
sentence") discourages a closing recap. Re-check at the next gate. If it recurs, consider
exempting the last section's wrap-up from rule 5, or checking the last 3 lines in the runner's
heuristic.

## Acceptance Criteria (proposal, to be planned)
- [ ] A bounded global length repair: when the total is over +10%, trim or regenerate the most over-budget section(s) with a word target. The number of passes is capped, and the budget is separate from other repairs.
- [ ] The mixed word-count + repetition case gets the length repair first, then the existing repetition check or repair.
- [ ] Thresholds unchanged. A new gate reaches 5/5 B1 completion.

## Erratum (PM, 2026-09-23, while planning Phase 17)

The Summary above (copied from the Gate B-7 report) says the pipeline has "no repair for a global total overshoot". **That is wrong.**
Task 14.3 item 6 already runs one last-section budget repair when the total is outside ±10%.
The checkpoints show the real failure mechanics:
- **Run 1:** at first validation the total was inside range, so the budget repair was skipped.
  The repetition repair then inflated section 2, taking the total to 1,124, and repetition was
  still 1.07%. Nothing re-checks the length afterwards.
- **5-min sample:** the last-section budget repair *did* fire. It asked for 237 words and got
  315. The overshoot sat mostly in section 2.

The conclusions stand: 16.6 would not have helped, and the length path needs work. The fix
direction is now in `docs/implementation/phase-17-global-length-repair.md` §0.
