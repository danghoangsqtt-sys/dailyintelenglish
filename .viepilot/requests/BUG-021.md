## Summary
`.viepilot/ARCHITECTURE.md`'s Diagram Applicability Matrix had this row:
`| event-flows | optional | WebSocket streaming TTS | — |`

This directly contradicted the corrected System Overview text diagram 35 lines above it
in the *same file* (fixed under ENH-007 / Task 10.2/11.1), which explicitly reads:
`↕ REST API (synchronous, polling — no WebSocket/SSE anywhere in the app)`

Grepped `app/` directly: zero WebSocket usage anywhere. Also confirmed via
`app/api/audio.py`/`app/api/video.py`'s own docstrings that even the `GET /status`
polling routes are "a plain polling GET, not real Server-Sent Events" — a deliberate,
already-documented deviation from an old SSE label. So there is no event-driven flow
of any kind in this codebase — the matrix row's rationale was never true, and the
ENH-007 fix (which corrected the System Overview text) missed updating this row to
match.
