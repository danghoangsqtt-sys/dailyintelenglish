# ENH: ffmpeg subprocess calls have no timeout — a hung render blocks forever

## Summary
`app/services/video_service.py:120` and `:154` call `subprocess.run(command, capture_output=True, text=True)`
with no `timeout=`. The calls correctly run in `asyncio.to_thread`, so the event loop is fine,
but an ffmpeg process that hangs (a bad input file, a stuck GPU encoder, a blocked output
file on Windows) keeps the video status `rendering` indefinitely, and the user can't retry.

## Acceptance Criteria
- [ ] Both calls pass a generous timeout derived from the target duration (e.g. `max(300, 4 × duration_s)`).
- [ ] `subprocess.TimeoutExpired` maps to the existing video error status and message, and the partial output is cleaned up.
- [ ] A test using a fake command that sleeps past a tiny timeout.
