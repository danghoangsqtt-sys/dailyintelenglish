# Task 76.2 — Shared folder panel in Step 1 and Step 7

Status: verified (2026-10-23; 2 focused Playwright checks passed); depends on 76.1.

## Objective

Make the existing project-folder panel choose a Topic parent, select legacy or hierarchical behavior for the current project, and preview the exact destination used by sync/open.

## Paths

- `frontend/static/js/project_folder.js`: replace the “shared series folder” copy, show layout mode and resolved destination, keep legacy projects in legacy mode until a user switches, and pass mode on save.
- `frontend/static/js/api.js`: expose the export path preview request through the existing API wrapper.
- `frontend/static/css/style.css`: style only the small mode/destination additions using existing tokens and panel conventions.
- `frontend/static/js/i18n_vi.js`: translate new visible panel text if the existing translation path requires it.
- `tests/test_project_folder_browser.py`: test the panel in Step 1 and Step 7, new-project hierarchy default, legacy preservation, and path preview/actions.

## File-Level Plan

1. Inspect the existing browser-test harness and i18n mechanism; add the focused module alongside the other `*_browser.py` tests.
2. Keep the existing shared panel and checkbox list. Add concise helper text and a clear mode control, not a new screen.
3. For a project with a legacy export setting, render its existing mode and path. Changing to topic hierarchy must be a user action; do not silently reinterpret the saved legacy path.
4. For a new project, prefill a saved Topic parent when available and default to hierarchical mode. Show a preview in the form `<parent>/<topic>/<series>/<Ep NN - title>` or `<parent>/<topic>/<project name>`.
5. Save mode and checked component keys through the current export API; preserve action locking/error state, Open folder and Stop saving behavior.
6. Run the focused browser checks and JS syntax validation.

## Best Practices

- Reuse the existing panel in both pages and preserve its current checkbox defaults.
- Do not let helper text imply that the internal project database is copied.
- Keep status messages accessible through the current `role=status` element.

## Risks

A returning legacy project can be redirected accidentally if the UI defaults its mode from the new-project path. Test legacy and new projects as separate journeys.
