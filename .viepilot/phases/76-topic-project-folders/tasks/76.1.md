# Task 76.1 — Topic export persistence and path resolver

Status: verified (2026-10-23; 18 focused backend/export tests passed)

## Objective

Persist per-Topic parent paths and explicit legacy/hierarchical mode; resolve safe Channel Plan and standalone destinations without changing existing legacy export semantics.

## Paths

- `backend/db/migrations/039_topic_export_roots.sql`: add the shared Topic root table and `project_exports.layout_mode` with a `legacy` default.
- `backend/content/export_service.py`: compute topic identity, sanitize folder labels, detect sibling collisions, resolve hierarchy, retain legacy resolver, and return parent plus actual folder in API views.
- `backend/api/export.py`: validate hierarchical root paths, save/sync using the correct mode, and open the resolved project folder with a useful parent fallback.
- `tests/test_phase41_export.py`: preserve existing legacy behavior assertions.
- `tests/test_phase76_topic_export.py`: cover migration compatibility, per-Topic root reuse, standalone paths, episode paths, folder safety/collisions, and selected-file syncing.

## File-Level Plan

1. Inspect the migrations and current export settings on a disposable test database.
2. Add an additive migration; never rewrite or backfill existing output paths.
3. Implement Topic identity and Windows-safe component resolution. Keep ordinary labels readable; suffix only colliding sibling names.
4. Keep `destination()` behavior for `legacy`. Use the new hierarchy only when a project explicitly saves `topic_hierarchy` mode.
5. Save/check the shared parent root under the Channel Plan Topic ID or normalized freeform project Topic. Retain selected component flags per project.
6. Return enough fields for the UI to show the chosen parent, mode, resolved path and last sync state. Ensure sync and open use the same resolver.
7. Add a read-only folder-preview endpoint so the panel can show the resolved path before saving.
8. Add focused tests, then run existing Phase 41 export tests and new Phase 76 tests.

## Best Practices

- Use additive SQL migrations and existing transaction helpers.
- Keep filesystem writes outside database locks; preserve the current sync lock and settings timestamp guard.
- Never delete or move files during a mode or root change.
- Validate all derived path components and make collisions deterministic across machines.

## Risks

The Channel Plan and standalone topic identities differ; accidentally keying by display label could merge unrelated Channel Plan Topics. Legacy output paths must remain byte-for-byte equivalent in meaning after migration.

## Verification

- `ruff check backend/content/export_service.py backend/api/export.py tests/test_phase76_topic_export.py`
- Verify the migration on a disposable database containing a pre-migration `project_exports` row and check its legacy destination remains unchanged.

Added migration039, stable Topic root suggestions, explicit legacy/hierarchical settings, Windows-safe paths and a read-only preview route. Existing records default to legacy. The Phase 41 plus Phase 76 backend export suites passed: 18 tests.
