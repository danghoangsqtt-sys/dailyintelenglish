# 75.1 — Isolated OmniVoice worker and synthesis dispatch

Status: implemented; focused service/API checks passed (2026-10-23).

## Objective

Integrate OmniVoice as an optional local engine without touching the app venv. Dispatch whole lines through a dedicated worker, map supported vocal cues to OmniVoice tags, use the shared GPU lease, and surface unsupported ahem/model/GPU errors without silent Edge fallback.

## Paths / allowed_files and file-level plan

- `backend/ai/tts/omnivoice_service.py`: readiness, path validation, worker process protocol and timeout/error conversion.
- `backend/ai/tts/omnivoice_worker.py`: dedicated-env entrypoint, whole-line Voice Design generation, offline-only local model loading, WAV response and process cleanup.
- `backend/ai/tts/tts_service.py`: engine dispatch while preserving the current Edge path and common cache write.
- `backend/api/tts.py`: report the selected engine when an already cached line is reused.
- `backend/ai/tts/vocal_cues.py`: pure conversion of supported app tags to `[laughter]`/`[sigh]`; reject unsupported ahem.
- `backend/ai/image/gpu_model_manager.py`: bounded registered eviction hook if needed so the model worker cannot strand VRAM against other consumers.
- `backend/core/config.py`, `backend/core/constants.py`: optional worker/model paths, timeout and measured/configurable VRAM threshold.
- `backend/core/voice.py`: include engine and design inputs in revision/fingerprint; keep Edge identity validation engine-specific.
- `tests/test_omnivoice_service.py`, `tests/test_tts_service.py`, `tests/test_vocal_cues.py`, `tests/test_gpu_model_manager.py`: mocked inference, routing, cue/error behavior, lease/eviction and cache identity.

## Best practices

- Do not import Torch/OmniVoice in the app process; do not alter `.venv`/`.venv-image`.
- Use a one-shot child process per line so its CUDA context and model are released before the GPU lease ends.
- Run subprocess/I/O outside the event loop and database transaction; use timeouts and controlled output paths.
- Do not log dialogue or design prompts. Validate output audio before caching.
- Never invent word boundaries or silently change the selected engine.

## Risks

Dedicated CUDA wheels and model weights are large; Windows subprocess shutdown and path resolution need explicit handling. Local model and CUDA inference/peak-memory measurements remain unverified in this workspace.

## Verification

Run focused tests for cue conversion, engine selection, unavailable model/GPU, worker failure, GPU serialization/eviction, and fingerprint invalidation; then Ruff and Python syntax checks. Local inference requires the separate environment and model download and is reported separately.
