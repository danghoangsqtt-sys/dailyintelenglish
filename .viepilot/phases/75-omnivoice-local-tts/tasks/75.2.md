# 75.2 — Speaker engine selection and Voice Design preview

Status: implemented and focused API/browser checked (2026-10-23); local audio review remains pending.

## Objective

Let users explicitly select Edge or OmniVoice per speaker, edit a Voice Design description, preview it, and see whether the local OmniVoice runtime/model is ready. Preserve Edge defaults and character profile settings.

## Paths / allowed_files and file-level plan

- `backend/schemas/project.py`: accept both supported engines; validate engine-specific voice IDs/settings.
- `backend/schemas/tts.py`: engine-aware preview request and result without pretending OmniVoice has an Edge voice ID.
- `backend/api/projects.py`: validate/update Edge voice IDs only for Edge; preserve Voice Design settings and clear stale voice IDs on engine changes.
- `backend/api/tts.py`: report actual engine/model availability; route voice preview by selected engine.
- `backend/ai/tts/voice_preview_service.py`: isolated local OmniVoice audition and existing bounded preview storage.
- `frontend/pages/step4_tts.html`, `frontend/static/js/step4_tts.js`: per-speaker engine choice, conditional Edge picker vs Voice Design prompt, readiness/error guidance, preview and save.
- `frontend/static/js/i18n_vi.js`: Vietnamese labels/help/errors.
- Tests: `tests/test_projects_api.py`, `tests/test_tts_api.py`, `tests/test_tts_audio_browser.py`, `tests/test_voice_preview.py`.

## Best practices and risks

Keep all network/service logic in backend API/service layers; use centralized frontend APIs and double-submit guards. Engine changes must increment voice revision and invalidate the old audio. Do not offer an unavailable local engine as ready, and do not send dialogue/audio to Hugging Face.

## Verification

Targeted API and browser checks: Edge default and unchanged picker, OmniVoice selection/persistence/reload, conditional controls, preview, not-ready state, and error path. Run `node --check` on changed JavaScript.
