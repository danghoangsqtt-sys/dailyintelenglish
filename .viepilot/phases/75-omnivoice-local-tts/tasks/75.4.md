# Task 75.4 — Package and install desktop 2.0.0

Status: verified (2026-10-23; local package/install complete, local OmniVoice inference remains a separate open gate)

## Objective

Build reproducible Full and Lite Windows desktop distributions for version 2.0.0 under `dist/2.0/`, create ZIP setup packages and SHA-256 checksums, and install the Full build over the current local desktop distribution while retaining a verified database and prior-app backup.

## Paths

- `scripts/package_desktop.ps1`, `scripts/create_setup_zip.py` — build both editions into a fresh versioned directory, create verified setup archives and checksums, and refuse to overwrite an existing version folder unless resuming an interrupted build.
- `scripts/build_exe.ps1` — set the new version default and package runtime metadata.
- `daily_intel_english_studio.spec` — ship the standalone OmniVoice worker script required by the isolated interpreter in a frozen build.
- `backend/ai/tts/omnivoice_service.py` — resolve the optional interpreter from the external workspace and the worker script from bundled resources.
- `.viepilot/phases/75-omnivoice-local-tts/{PLAN.md,PHASE-STATE.md,tasks/75.4.md}` — record scope, status, verification and outcome.
- `README.md`, `CHANGELOG.md`, `.viepilot/PROJECT-META.md`, `.viepilot/HANDOFF.json`, `.viepilot/TRACKER.md`, `.viepilot/ROADMAP.md` — document the local 2.0.0 package and current install accurately.
- `docs/user/second-machine.md`, `docs/operations/omnivoice-local-tts.md` — document 2.0 package names and the optional OmniVoice setup path.
- `dist/2.0/` — generated Full/Lite setup folders, ZIPs and checksums; ignored build artifacts.

## File-Level Plan

1. Resolve frozen OmniVoice subprocess paths: bundle the worker as a data file, call it by absolute script path, and locate the isolated Python environment under the configured external workspace. Preserve source-mode defaults and the external model directory.
2. Add a packaging orchestrator that refuses to overwrite `dist/2.0`, builds Full then Lite with version 2.0.0, writes clear setup notes, ZIPs each app folder and verifies SHA-256 manifests.
3. Update user-facing and project metadata from 1.7.0 to 2.0.0 where they describe the current version; record features from Phases 73–75 without claiming local OmniVoice inference is ready. Preserve historic changelog entries.
4. Run focused OmniVoice tests, packaging-script syntax checks, metadata/ZIP/checksum verification and the app build. Install the verified Full folder through `scripts/install_desktop.ps1`, which performs the idle-job check and database/app backup. Verify the installed EXE metadata, shortcut, previous-app copy and SQLite backups. Do not launch the production desktop during packaging because its normal startup can start scheduled production work; report first-run health separately.

## Best Practices

- Keep `dist/2.0` separate from the current installed `dist/DailyIntelEnglishStudio`; do not delete or overwrite the current install during build.
- Do not package model weights or Torch into the app. Edge stays default; OmniVoice remains optional and reports unavailable until its separate CUDA environment/model are installed.
- Preserve all existing uncommitted source edits. Do not stage, commit, push or publish a GitHub release.
- Treat generated ZIPs as local hand-off packages, not an assertion that they are signed or publicly released.
