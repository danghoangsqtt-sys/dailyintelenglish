# 74.2 — AI annotation after script validation

Status: verified (2026-10-23). Structured cue plan, fallback, versioned durable job, legacy generate and one-line regeneration covered by targeted tests.

## Objective

Deliver AI-generated scripts with sparse context-appropriate cues without changing validated dialogue, speaker identity, CEFR/budget logic or durable job behavior.

## Paths / allowed_files and file-level plan

- `backend/ai/prompts/script/vocal_cue_annotation.txt`: template asks for zero-or-more cue placements only; includes context, speaker traits, variant choice, frequency and serious-topic restraint; no prose rewrites.
- `backend/ai/llm/prompt_loader.py`: render the template from files off the event loop with bounded line context.
- `backend/content/vocal_cue_annotation.py`: Pydantic plan/entry schema and deterministic service; validate zero-based line index, after-word index, enum/variant compatibility, one per line, total `ceil(minutes * 2)` quota, spacing and immutable cleaned text. Return clean lines plus warning on optional provider failure.
- `backend/core/constants.py`: named context bounds and spacing/quota constants used by the annotation service.
- `backend/content/script_pipeline.py`: call annotation after all repairs/global checks and before `server_lines`; heartbeat while waiting, then recheck cancel/config hash immediately before the publish transaction. Restart must never expose partial annotation.
- `backend/content/script_service.py`: apply compatible annotation to deprecated synchronous generation and single-line regeneration, preserving existing line/speaker contracts.
- `backend/api/projects.py`: supply current episode context/budget for one-line regeneration and retain no-lock provider call shape.
- `backend/api/ai_jobs.py`: mark newly created production script jobs with a versioned annotation flag in their durable input snapshot; pre-feature jobs keep their original behavior on recovery.
- `tests/test_vocal_cue_annotation.py`: planned schema, insertion, quotas, no-cue, invalid-placement, provider-failure and immutability cases.
- `tests/test_script_pipeline.py`: planned post-validation ordering, restart/cancel/config-race and clean-script fallback cases.
- `tests/test_script_service.py`, `tests/test_script_api.py`: planned legacy and one-line regeneration cases; other edited lines remain intact.

## Risks and acceptance

No LLM call while holding the shared write lock. A failed optional cue pass cannot fail the validated script. The model never returns replacement text or speaker IDs. One-line regeneration must consider cues already in other lines so the episode quota is not exceeded. No schema migration is planned. Verification is future work; no tests run during crystallization.
